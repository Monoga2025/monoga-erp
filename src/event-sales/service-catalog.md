# Catálogo de servicios — borrador local T5

**Uso interno · borrador en español · evidencia local únicamente.** No es una cotización, promesa de capacidad ni publicación.

## Cómo leer este catálogo
Cada línea parte de un dolor que debe confirmar el cliente. El estado indica la evidencia disponible: `prototype` = artefactos o guías locales demostrables, sin verificación como producto vigente; `blocked` = no hay evidencia suficiente para una demo segura. No se incluyen precios, resultados, clientes ni plazos no verificados.

## 1. Presencia digital y Growth
- **Dolor a confirmar:** propuesta poco clara, web que no guía la decisión o dificultad para convertir una consulta en conversación.
- **Qué se puede explorar:** maqueta local de estructura, mensaje, CTA y preguntas de validación.
- **Estado:** `prototype`; no implica publicación, analítica, SEO ni conversión verificada.
- **No afirmar:** tráfico, leads, conversiones, ROI, clientes, precio o disponibilidad.
- **Siguiente paso:** diagnóstico breve para priorizar una hipótesis y definir qué evidencia faltaría.

## 2. Recepción comercial y automatización
- **Dolor a confirmar:** consultas dispersas, respuestas manuales o seguimientos que se olvidan.
- **Qué se puede explorar:** flujo local supervisado para preparar una respuesta y registrar una próxima acción con datos sintéticos.
- **Estado:** `prototype`; requiere revisión humana y no prueba envíos ni integración activa.
- **No afirmar:** automatización continua, WhatsApp, entregabilidad, ventas, resultados o precio.
- **Siguiente paso:** mapear canales, responsables, datos permitidos y una prueba local acotada.

## 3. CRM y operaciones
- **Dolor a confirmar:** información dispersa, poca visibilidad del estado o ausencia de responsable y próxima acción.
- **Qué se puede explorar:** registro y pipeline local, con campos de dolor, consentimiento y siguiente acción.
- **Estado:** `prototype`; la evidencia local no verifica CRM remoto ni operación productiva.
- **No afirmar:** sincronización, integraciones, migración, capacidad de entrega, clientes o resultados.
- **Siguiente paso:** diagnóstico del proceso y definición del mínimo flujo que debe validarse.

## 4. Software y prototipos a medida
- **Dolor a confirmar:** proceso específico que no encaja en una herramienta existente o necesita una hipótesis de flujo.
- **Qué se puede explorar:** alcance, mapa de estados y prototipo aislado con datos sintéticos.
- **Estado:** `blocked` para presentar software de producción; un futuro prototipo requeriría alcance y validación separados.
- **No afirmar:** sistema disponible, integraciones, plazo, precio, soporte, clientes o resultados.
- **Siguiente paso:** sesión de alcance para separar problema, hipótesis, restricciones y criterio de aceptación.

## Consentimiento y límites
Antes de guardar datos o enviar este material, pedir autorización explícita para el canal y propósito. Registrar `granted`, `declined` o `unknown`; `unknown` no autoriza seguimiento. Ofrecer no recibir mensajes y detener el contacto ante un “no”. No usar listas de asistentes, inferir identidad o intención, ni enviar información a servicios externos. Toda cifra, cliente, resultado, precio o capacidad debe verificarse y autorizarse antes de incorporarse.
